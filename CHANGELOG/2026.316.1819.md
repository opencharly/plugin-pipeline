# 2026.316.1819 — fix(workflowkit): own the pipeline body corpus, and carry sdk#368's vocabulary fix in

## Summary

**The plugin-side follow-through of unit 1** (`TODO.md` 2.1, tracker `opencharly/spec#304`). Leg 2 moved the `kind: pipeline` body and its machinery into this repo; two things were left behind in the module that no longer declares them, and this PR picks both up so unit 1's last legs can delete the originals without losing anything.

### 1. `sdk#368`'s lowering fix is carried here

`sdk#368` (open since 2026-11-03) fixes a real defect at the authored→engine vocabulary boundary: the authored `on_error: fail` reached an engine whose enum only knows `stop` (so `fail` silently behaved as `continue`), and an unauthored `wait:` arrived empty against an engine enum that declares no default. Its diff targets `sdk/workflowkit/lower.go` — the file unit 1 moved here in leg 2 — so landing it there would fix a file that is about to be deleted, and deleting that file first would orphan the fix. It is carried into this repo's `workflowkit/lower.go` (the helper calls are already package-local here), with its test as `workflowkit/vocab_boundary_test.go` retyped to `params.*`.

`sdk#368` is closed as **superseded** by this PR, its branch left unmerged, so the fix has exactly one home.

### 2. The body's closedness corpus moves with the defs

The `kind: pipeline` body defs are this repo's CUE since leg 2, but their corpus lived in `spec` (`spec/pipeline_test.go`'s `TestPipelineValueClosedness` and the authored-def cases of `spec/workflow_envelope_test.go`) because the defs did. Unit 1's last leg deletes the defs from `spec`, so the corpus moves first: `pipeline_schema_corpus_test.go` judges the composed served schema through `schemacompose.ServedSchema` — the same call `schema_test.go` makes, i.e. the value this plugin actually serves — and keeps every case, including the two deliberate Go-rule exemptions (the exec-arm XOR) and the IR-only bound on `#PipelineApproval`.

**29 closedness cases + 5 authored-surface cases**, and the compile-time assertion that the authored schedule's `Args` field is `map[string]any` (moved from `spec/workflow_arg_list_wire_test.go`).

**No schema, params or provider surface changes.** `schema/pipeline.cue` is untouched; the generated params reproduce.
