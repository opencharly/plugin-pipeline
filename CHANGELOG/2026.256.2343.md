# 2026.256.2343 — fix(pipeline): eval-lane media dir + check-prose YAML rendering

## Summary

Three eval-lane defects found live on a 16-lane, 32-PR run, plus documentation notes. All in the pipeline candy; no core/sdk change.

**1. The root cause of the lost media: `rc.media` was never populated.** `executor.go` assigned `rc.media = mm(p.Media)`, but `p.Media` is a `params.MediaSpec` **struct** — `mm()` is `v.(map[string]any)` and returns nil for a struct — so `rc.media` was ALWAYS nil. The adjacent `report:`/`skills:` assignments correctly wrap the struct in `mapOf()`. Fixed to `rc.media = mm(mapOf(p.Media))`.

**2. The media stage ignored the pipeline-level `media.dir`.** `runMedia` resolved its output dir only from its own `raw["dir"]` (a field the `#MediaStage` schema does not even admit), so it always wrote the legacy `media/pr-<pr>-<calver>` default while `media_gate` / `ledger-gate` / the report expect `media/<calver>/pr-<pr>`. `mediaDir()` now resolves: the stage's own `dir:` → the pipeline-level `media.dir` → the legacy default.

**3. Check prose was emitted as a bare YAML scalar.** `renderCheckBlock` wrote `- check: <what>` unquoted, so any prose containing `: ` (live case: ``declares `_watch: true` …``) produced invalid YAML; because `bed-render` runs `charly box validate` over the WHOLE project, one malformed oracle bed failed EVERY concurrent lane. `yamlScalar()` now single-quotes both the prose and the assertion (doubling quotes, folding newlines).

**Behaviour change documented (prior review finding 3):** `mediaDir` now joins a RELATIVE result — including the legacy default — with `rc.workdir`; the old code joined only the `raw["dir"]` branch. Noted in-source.

**Out of scope, routed to the named batch `feat/live-lane-eval-batch`:** the live run's `media_gate` `size < min` miss (an mp4 of a mostly-static screen H.264-compresses to 3214 bytes, under the 4096 minimum) is a **media-contract / eval-duration** matter on the same lane-quality surface as the shell-readiness work — NOT the dir-resolution this PR fixes. It is routed there by name, not parked.

- `executor.go` — `rc.media = mm(mapOf(p.Media))`.
- `media.go` — `mediaDir()`; workdir-join note.
- `render.go` — `yamlScalar()` + the 10134 RCA note.
- Tests: `media_test.go` (`TestMediaDir_FromPipelineSpec` mirrors the executor assignment — fails under the old `mm(p.Media)`; plus fallback / precedence / legacy), `render_scalar_test.go` (quoting + the real 10134 prose parses quoted, fails bare), `plan_features_test.go` expectation updated.
