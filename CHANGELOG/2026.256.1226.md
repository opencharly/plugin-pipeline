# 2026.256.1226 — feat(pipeline): ref-resolve the agent-stage skills.corpus

## Summary

The agent-stage `skills.corpus` path was read raw and only joined with `--workdir`, so a lane could only point at a skill corpus **inside its own tree**. This resolves the corpus through the pipeline's EXISTING reference grammar (`$pr` / `$calver` / `$workdir` / `$env.NAME` / `@stage.output`) before the workdir join — no new mechanism.

Why it matters: `opencharly/eval-omarchy`'s eval-lane corpus is moving from hand-authored loose files to the **generated** marketplace projection (`charly marketplace generate` → `<marketplace>/distros/skills/omarchy-eval-*`). The lane must point at that generated corpus outside its own workdir, e.g. `skills.corpus: "$env.EVAL_UMBRELLA/marketplace/distros/skills"` — impossible with a literal path without hard-coding (R4).

- `candy/plugin-pipeline/agent.go` — new `skillCorpus(rc)` helper (ref-resolve + relative join), placed ABOVE `runAgentStage` so its doc comment stays adjacent; `runAgentStage` uses the helper.
- `candy/plugin-pipeline/schema/pipeline.cue` — document the ref-resolution (SDD single source); `params/cue_types_gen.go` regenerated.
- `candy/plugin-pipeline/skills_corpus_test.go` — **5 cases**: `$env` ref resolves (`omarchy-eval`'s real form), `$workdir` ref resolves, relative literal joins the workdir, absolute literal unchanged, nil ctx.
