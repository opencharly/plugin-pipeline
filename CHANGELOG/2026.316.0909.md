# 2026.316.0909 — feat(schema)!: import the contract's LLM defs instead of restating them

## Summary

`schema/pipeline.cue` restated the contract's six LLM definitions as local twins —
`#LLMSpec`, `#LLMParams`, `#LLMResponseFormat`, `#LLMReasoning`,
`#LLMStreamOptions`, `#LLMNamedToolChoice` — and the generated `params` package
carried its own `LLMSpec` / `LLMParams` structs beside them. ONE NAME, ONE HOME: the
contract module (`github.com/opencharly/spec/schema`) owns that vocabulary — the
shapes the `vision:` check verb authors against, and the defs that generate
`spec.LLMSpec` / `spec.LLMParams`, the types the shared SDK `llmkit` client consumes.
The schema now IMPORTS them and declares only its own authoring shapes; the local
copies, the JSON bridge that translated between the two declarations, and the parity
test that existed only to keep the copies honest all retire in the same change (R2).

  git --git-dir="$store" ls-tree -r --name-only "$sha" 2>/dev/null | grep -qE '(^|/)schema/.*\.cue$' || continue

echo "pinned submodules: $total"; echo "with a schema/*.cue dir: $withcue"
echo "importing github.com/opencharly/spec/schema: $importing"
