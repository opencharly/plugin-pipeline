The def RENAME matters: the host compiles base ++ EVERY plugin into ONE CUE
instance, and two plugins defining the same def name silently unify — so a generic
`#ResponseFormat` in this mirror could collide with another plugin's same-named
def. The mirrored defs now use spec's `#LLM*` names (the spelling plugin-vision
also mirrors), and `schema_parity_test.go` asserts both the field-set equality
against the ACTUAL spec source and the absence of a generic name (both
mutation-verified). This is why the params file and the schema appear in the diff.

What remains is the engine's thin adapter:
- `resolveLLM` — the documented layer resolution (entity → stage → `EVAL_LLM_*`
  env → default) expressed against `llmkit.Config`;
- the transcript ALIASES (`chatMsg = llmkit.Message`, `chatToolCall =
  llmkit.ToolCall`) so the agent turn-loop CODE is unchanged (only agent.go's
  header comment changed — it names the shared client);
- `toSpecLLM` — ONE non-lossy bridge to the contract types (see below);
- the stage-level `llm:` decode and the integer readers.

`resolveLLM` now RETURNS an error: the first revision of this companion SWALLOWED
the bridge's marshal/unmarshal failure and returned a zero `spec.LLMSpec`, which
would silently drop the whole authored `llm:` block and fall back to defaults —
a silent config-resolution failure (R1). One generic `toSpecLLM(any)` replaced the
two copy-pasted bridges (R3).
