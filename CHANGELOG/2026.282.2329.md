# 2026.282.2329 — fix(agent): append a skill's references/*.md to the stage prompt — progressive disclosure was being dropped whole (plugin-pipeline#36)

## Summary

`opencharly/plugin-pipeline#36`. An `agent:` stage resolved its `skill:` refs by reading **only** `<corpus>/<skill>/SKILL.md`, so `references/*.md` — the progressive-disclosure split the skills contract prescribes — were **unreachable from a pipeline stage**.

The contract is *"an entry `SKILL.md` plus sibling `references/*.md` files in the same skill directory, **loaded on demand by path**"*. **A pipeline stage has no harness to load them on demand**: there is no model with a filesystem, no follow-up read, no path the stage ever receives. So the on-demand half of the contract silently became *no disclosure at all*, and the code's own comment — *"a declared skill that does not resolve is a LANE DEFECT"* — shows it already treats a **missing** skill as fatal while treating a **present-but-partial** one as complete.

## The change

`skillBundle(corpus, name)` is now the one place a declared skill becomes system-prompt text: the entry `SKILL.md`, then every `references/*.md` beside it, **in sorted order** so one skill yields one system prompt run after run. The stage loop is five lines and calls it — one call site, one definition.

Three properties are deliberate:

- **`.md` only** — the split is defined as `references/*.md`; a stray sibling in that directory is not part of the skill and is not pulled in.
- **Sorted** — a system prompt that reshuffles between runs is a different prompt, and an agent stage's determinism should not depend on directory order.
- **A missing skill still fails the stage** — that behaviour is load-bearing (a declared ref must resolve), and the test asserts it so a future refactor cannot quietly downgrade it to a warning.

## How tested

```console
$ gofmt -l .        # clean        $ go vet ./...   # rc=0        $ go test ./...   # ok
```

`TestSkillBundleAppendsReferences` builds a real corpus on disk — a skill with two references and a non-`.md` sibling, and a skill with none — and asserts the bundle carries the entry, both references, **nothing else**, in sorted order; that a skill with no references is byte-for-byte unchanged; and that an absent skill still errors.

**Proven able to fail, by a behavioural mutation** (the first attempt was confounded by a build break, so it was replaced with one that is not):

```console
$ sed -i 's|"references", "*.md"|"references-DISABLED", "*.md"|' verb_agent.go
$ go test ./... -run TestSkillBundleAppendsReferences
--- FAIL: TestSkillBundleAppendsReferences (0.00s)
```

so removing the disclosure cannot pass.

The issue left open *"whether any shipped pipeline stage currently declares a `skill:` whose `SKILL.md` carries references"* — a corpus survey. **It is not needed to fix this**: the code was wrong whether or not a shipped stage hit it, and the fix is the same either way.
