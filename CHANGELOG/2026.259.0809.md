# 2026.259.0809 — feat(pipeline): schema-first emit stage + schema-validated ledger dump

## Summary

Adds a `kind: emit` stage to the pipeline engine — the generic **schema-first artifact writer**. A structured value (assembled from the reference grammar, with array/map leaf types preserved) is validated against an authored CUE schema with **Concreteness required** BEFORE any bytes are written, then marshalled through the CUE YAML encoder. The schema may be **(1)** a plugin def (`#Foo`), **(2)** a committed `.cue` file (`path.cue` or `path.cue#Def`), or **(3)** a literal CUE source. String leaves may carry `${var}` markers (indent/bullets/…), so a prose field is composed without a hand-written YAML template.

**Why.** The `generate` stage renders a free-form string template — a writer the caller cannot validate at authoring time. A single unquoted scalar containing `": "` (e.g. `what: Docs-only change: …`) produces YAML no parser can read; a lane that then re-reads its own committed record (the render-once cache) crashed on the NEXT run with `unreadable committed plan`. Schema-first emission makes that class impossible: a value that violates the schema fails the stage informatively instead of shipping bytes no reader can consume.

Also changed: the per-run ledger dump (`stage-findings.yml`) is now written schema-first against `#StageFindings`, and the `README.md` run-line's stage list names `ade`/`emit`.
