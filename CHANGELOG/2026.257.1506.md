# 2026.257.1506 — feat(pipeline): committed-plan cache + per-marker render transforms

## Summary

Five general pipeline-engine gaps, each surfaced while declaring ONE self-contained per-PR evaluation record. All are engine-level; the lane work rides this PR's tag.

1. **Agent-stage `cache:`** — a committed-plan freshness primitive. When the artifact exists and its `key_field` equals the ref-resolved `key` (e.g. `$env.PR_HEAD_SHA`), the declared outputs are READ from the file and the agent **never runs**; a stale or missing key authors fresh. Render-once-per-`<key>` (no re-triage on an unchanged head). A hit **requires every declared output and validates each against its `#OutputType`** via the same `validateTypedValue` the live reply uses (R3) — a partial or mistyped committed plan is a hard error, never an `ok` with an output silently absent.
2. **Per-marker generate transforms** (`${var:negate}` / `${var:json}` / `${var:yaml}` / `${var:indent}` / `${var:bullets}`) — applied to that marker **alone**, so ONE template renders both the treatment bed and its negative-control twin into a single discoverable file, plus a structured record (native YAML blocks + indented prose + bullets). The transform set is **closed**: an unknown transform (`:negte`) and `:negate` on a non-list are hard errors — a typo can never silently render the control as a copy of the treatment.
3. **ADE bed resolved BY ENTITY NAME** — `bedPlanOps`/`adeVerdict` hardcoded `pr-beds/pr-<N>/charly.yml` AND parsed a flat top-level `plan:`. A real bed is name-first (`<bed>: { vm: { plan: [...] } }`, scalar `version:` header), so the compiled-in drive read **ZERO ops and returned a vacuous `PASS code=0`** over no checks. Now resolved via the loader's own discovery. A missing entity, OR a present entity with no/empty plan, is a HARD error. The flat-top-level fallback is removed (it never matched a real bed; R5).
4. **`ledger_gate` single media-min source + structured step rows** — takes min sizes from the entity `media.min`; surfaces the per-step outcomes it already parses (`eval_steps`/`control_steps`).
5. **`${var:indent}` / `${var:bullets}`** — block-scalar + markdown-list rendering for the record's user-voice prose.

SDD: `schema/pipeline.cue` edited first; `params/cue_types_gen.go` regenerated with the pinned `cue v0.16.1`.

### R3 — the two media-min tables, and which is canonical

Before this PR the engine carried a **hardcoded** min table inside `probeLedgerGate` that never consulted the entity's `media.min`:

```
# engine, origin/main candy/plugin-pipeline/probes.go:384
probeMediaGate(map[string]any{"dir": mediaDir, "files": []any{"cast","gif","mjpeg","mp4","png"},
    "min": map[string]any{"cast":200,"gif":1024,"mjpeg":4096,"mp4":4096,"png":1024}}, rc)
```

Meanwhile the entity that owns the layout declares its own:

```
# eval-omarchy/charly.yml:1535 (the entity — the authoritative lane values)
min: { cast: 200, gif: 1024, mjpeg: 4096, mp4: 512, png: 1024 }
```

So `ledger_gate` ignored the lane's `media.min` (mp4 512) and gated on its own hardcoded 4096 — **two drifting tables**. The fix makes the entity's `media.min` authoritative and keeps the engine fallback **byte-identical to the table it replaces** (mp4 **4096**):

```go
// candy/plugin-pipeline/probes.go — the fallback is UNCHANGED; media.min overrides
defMin := map[string]int{"cast": 200, "gif": 1024, "mjpeg": 4096, "mp4": 4096, "png": 1024}
```

`TestMediaGateSpecUsesPipelineMin` pins **every** engine default value (mp4 4096 included) so a silent loosening cannot recur, plus the override path.
