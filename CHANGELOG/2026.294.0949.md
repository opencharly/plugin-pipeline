# 2026.294.0949 — fix(pins): carry the sdk lowering that spells responseSchema, so the input gate runs

## Summary

Pin bump only: the two modules this repo lowers through, no Go source change.

`sdk/workflowkit.Lower` rewrites `response_schema` -> `responseSchema` — the spelling every lobster
consumer reads — from `sdk v0.2026276.1822` onward. This repo pinned `v0.2026276.255`, which predates
it, so the lowered file carried the snake_case key and every `input:` gate ended its run with
`Workflow step ask input.responseSchema must be an object` (`opencharly/plugin-pipeline#45`). That one
step was the last red step in `check-pipeline-local` here and in `plugin-lobster`'s
`check-lobster-local`.

- `sdk` v0.2026276.255 -> **v0.2026293.2302**
- `spec` v0.2026277.1407 -> **v0.2026289.611** (the version that sdk tag requires; newer than the pin
  it replaces)
- `go 1.26.4` -> `go 1.26.8`, the directive the bumped transitive deps (grpc 1.83.2, protobuf) make
  `go mod tidy` record — it is part of this diff, not an accident of it
- the sdk bump adds **4** new indirect requires — `containerd/containerd/v2 v2.4.1`,
  `containerd/errdefs v1.0.0`, `containerd/log v0.2.0`, `sirupsen/logrus v1.10.2` — and **bumps 8**
  existing indirect modules: `pelletier/go-toml/v2` v2.2.4 -> v2.4.3, `go.yaml.in/yaml/v3` v3.0.4 ->
  v3.0.5, `golang.org/x/net` v0.57.0 -> v0.58.0, `golang.org/x/sys` v0.47.0 -> v0.48.0,
  `golang.org/x/text` v0.40.0 -> v0.42.0, `grpc` v1.61.0 -> v1.83.2, `genproto/googleapis/rpc`
  -> v0.0.0-20260825221802-da73d73af1c5, `protobuf` v1.36.12-0.20260120151049 -> v1.36.12. Both
  counts are derived from the two `go.mod` revisions, not from reading the diff by eye.

Why not the current release: **`sdk v0.2026294.615` is not reachable without a code change.** Every sdk
tag from `v0.2026294.615` onward requires `spec v0.2026294.550`, and that spec tag carries spec#262's
`workflow_args` widening, which rejects this repo's `map[string]string`:

```
$ go build ./...
# github.com/opencharly/plugin-pipeline/candy/plugin-pipeline
./cli.go:336:77: cannot use args (variable of type map[string]string) as map[string]any value in struct literal
```

Widening that map is a change to the front-end's arg path, i.e. a separate leg — filed as
`opencharly/plugin-pipeline#46`, not chased here. `v0.2026293.2302` is therefore the newest tag the
repo compiles against unchanged, and it carries the rewrite this PR exists for (three `responseSchema`
occurrences in that tag's `workflowkit/lower.go`).

Diff: 2 files, 89 insertions, 44 deletions, one commit, head `8b1f3c7`.
