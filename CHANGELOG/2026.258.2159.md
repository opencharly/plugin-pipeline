# 2026.258.2159 — fix(agent): stream the LLM call and bound it by IDLE, not whole generation (R1)

## Summary

**RCA (R1).** The pipeline's agent LLM call (`chat()`, `candy/plugin-pipeline/agent.go`) issued a
**NON-STREAMING** `POST /chat/completions` under a single `http.Client{Timeout: 5 * time.Minute}`.
With no `stream: true`, response headers arrive only after the ENTIRE generation completes, so
that 5-minute client timeout is a **whole-generation deadline**. A slow reasoning model (the
eval lane's `deepseek-v4.1-flash` cold-read) was cut off at 5 minutes with:

```
Post "http://localhost:11434/v1/chat/completions": context deadline exceeded (Client.Timeout exceeded while awaiting headers)
```

while the provider was still working — FAIL-HARDing the `eval-pr-plan` lane.

**This is the same defect class the org's `pr-validator` workflow already root-caused for
`plugin-review`** (a non-streaming request under a whole-generation deadline, `llm.go:80/92` +
`review.go:28`), and the remedy is the same: **stream, and bound the idle gap instead of the
total generation.**

### The fix

- `chatRequest` gains `Stream bool` and the call sends `stream: true` with
  `Accept: text/event-stream`.
- `chat()` now READS the SSE stream: content deltas are concatenated, and tool-call deltas are
  assembled by `index` (the OpenAI SSE shape — id/name in the first fragment, arguments
  appended in later ones).
- The request rides a **CANCELLABLE CHILD** of the caller's ctx, and the **IDLE watchdog**
  (`chatIdleTimeout`, default **3m**, overridable via `EVAL_LLM_IDLE_TIMEOUT`) **cancels it**
  when no chunk has arrived for that long; the watchdog is **re-armed on every chunk**, so a
  model that keeps emitting (reasoning deltas, tool-call deltas) is NEVER cut off and only
  genuine silence trips it.
- **Why cancel-the-ctx, not `resp.Body.Close()`** (the validator caught an earlier draft that
  used Close): in `net/http`, `bodyEOFSignal.Read` holds `es.mu` **across** the blocking
  `es.body.Read`, and `bodyEOFSignal.Close` blocks on that same mutex — so a `Close` from the
  watchdog goroutine just queues behind the in-flight Read and unblocks nothing. Cancelling the
  request's context makes `http.Transport` **tear the connection down**, which makes the blocked
  Read return an error. That is the standard-library way to abort a blocked body read.
- **A stall is NEVER silent (R1).** Even a turn with partial content errors on the idle trip (a
  truncated completion must not be mistaken for a finished one); a no-content, no-tool-calls
  completion errors too (the streaming-form equivalent of the removed `len(cr.Choices) == 0`
  guard).
- The trip flag is an `atomic.Bool` (the watchdog goroutine writes it; the main goroutine reads
  it — a plain bool was a data race, caught by `go test -race`).
- **No `http.Client.Timeout`** — that would be a whole-generation deadline again. The request is
  bounded by the caller's ctx plus the idle watchdog.
