### What changed

- `schema/pipeline.cue` now declares `#Pipeline`, `#PipelineValue` and the step/trigger/flow helpers, plus `_onError`/`_onErrorWord` (they travel with `#PipelineFlow`). External references stay the contract module's and become `schema.`-prefixed — `#StrVal`, `#Step`, `#TaskParamSpec`, `#WorkflowArgVal` — shared with `kind: task`, a candy plan and the workflow wire, so a pipeline body and the plan it lowers to cannot disagree. This is the same one-name-one-home rule `opencharly/plugin-pipeline#60` applied to the six LLM defs.
- The `kind` capability already declared `InputDef: "#PipelineValue"` (`plugin.go`), so the host resolves the gate through the provider's declaration and carries no knowledge of the kind.
- `workflowkit/` now holds `validate.go`, `lower.go`, `graph.go`, their tests and `testdata/`, moved from `sdk/workflowkit` with a **mechanical retype**: `spec.Pipeline*` → `params.Pipeline*`, the kind-blind helpers called as `sdkworkflowkit.*`, and no logic touched — which the byte-identical goldens below prove.
- `params/cue_types_gen.go` is regenerated in process by `spec/schemaparams.Generate` (the same function `charly candy params` calls); `TestGeneratedParamsAreCurrentAndReproducible` proves the committed file reproduces and that a second run is byte-identical.
- The docs follow the code: `AGENTS.md`, `README.md`, the repo's own `pipeline-skill:` source, the candy description, the root `charly.yml`, and every code comment that named the old home or `sdk/workflowkit`. Two comments the move made **stale** (`spec/schema/pipeline.cue` named as `#PipelineInput`'s home) are corrected here — that is this diff's own R1 finding, fixed rather than filed.
