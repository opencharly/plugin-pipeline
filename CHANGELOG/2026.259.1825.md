# 2026.259.1825 — feat(pipeline): replace the handcrafted OpenAI client with the official openai-go SDK + a fully-authored CUE param surface

## Summary

Replaces the engine's hand-written OpenAI client with the official
`github.com/openai/openai-go/v3` SDK, makes the whole request surface authorable
through the plugin's own CUE schema, and fixes every defect a measured
end-to-end run of the real `eval-pr-plan` lane exposed.

**Why.** The agent runtime hand-rolled the entire OpenAI-compatible wire path
(`chatRequest`/`chatMsg` structs, a `net/http` POST, a 121-line SSE parser) and
hardcoded every request knob. That client could not do vision, dropped
reasoning deltas, sent no `max_tokens`/`response_format`/`seed`/`stop`, and
silently dropped `tool_choice` (ollama's compat request struct has no such
field — the docs list it unsupported). It is now gone.

Two parts:

**1 — the SDK swap + full configurability (commit 37b23c9).**

- `schema/pipeline.cue` (SDD single source) → `params/cue_types_gen.go`: a new
  `#LLMParams` covering the general OpenAI chat-completions parameters
  (`temperature`, `top_p`, `max_tokens`, `max_completion_tokens`,
  `frequency_penalty`, `presence_penalty`, `seed`, `stop`, `response_format`,
  `reasoning_effort`, `reasoning`, `stream_options`, `parallel_tool_calls`,
  `tool_choice`, `logprobs`, `top_logprobs`, `user`, `metadata`, `logit_bias`,
  plus an `extra` escape hatch for undocumented fields). `#LLMSpec` gains
  `organization`, `project`, `timeout`, `idle_timeout`, `max_retries`,
  `headers`. `#ResponseFormat`/`#Reasoning`/`#StreamOptions`/`#NamedToolChoice`
  added; `#StageLLMSpec` gives each `#AgentStage` an `llm:` override. Both param
  defs are `close()`d — an unknown or wrong-typed field is a LOAD error naming
  the CUE path.
- `llm.go` (new): resolves `env > stage > entity > built-in default`
  field-wise, builds the client per call with explicit options, and maps the
  authored params 1:1 onto the SDK union. It uses `NewChatCompletionService`
  (NOT `NewClient`) so a stray `OPENAI_API_KEY`/`OPENAI_BASE_URL`/
  `OPENAI_CUSTOM_HEADERS` cannot hijack a lane; an empty resolved key sends NO
  `Authorization` header (the keyless local ollama needs none).
- `chat()` re-implemented on `NewStreaming` + `ChatCompletionAccumulator`,
  keeping the RCA'd IDLE bound (a per-chunk watchdog that cancels the request
  ctx — not a whole-generation deadline) and the empty-completion guard.
  ollama's non-standard `reasoning` delta (which the SDK accumulator drops) is
  read from the raw JSON, so a reasoning-only 200 is reported as a NAMED empty
  completion instead of a bare one — the real shape behind the intermittent
  lane failures.
- Vision: `chatVision`/`imageDataURL` send a screenshot as a base64 image_url
  content part DIRECTLY to the endpoint (ollama supports base64 data URLs only).
- `tools.go`: the catalog renders `openai.ChatCompletionToolUnionParam`.
- The wire structs (`chatMsg`, `toolCall`, `toolSchema`, `functionSchema`,
  `chatRequest`, `chatResponse`), the old `chat()` IMPLEMENTATION (the
  hand-built POST + manual SSE parser), and the hand-built tool JSON are
  replaced: `chat()` now takes the SDK message union and delegates to
  `chatMessages` (see Part 1 above), and `chatMsg` survives as the engine's
  internal transcript row fed to `toSDKMessages` — it is no longer a wire type.

**2 — the defects found by measuring (commit ffc3323).** Eleven, each
root-caused. Two were per-lane state collisions of the same class the ledger
OBJECT already fixed (RCA 2026.252.2210), never applied to the artifacts they
write:

- **`runBatch` reported SUCCESS for a failed batch** — it printed each lane's
  error then returned `0, nil` unconditionally, so a lane ending in the
  LOOP-GUARD escalation still printed `OK` and exited 0 (R7). A `laneReport`
  aggregate now makes any failed lane a non-zero exit.
- **`ade.go` passed the process-global `os.Getenv("PR_HEAD_SHA")`** instead of
  the per-lane value, contradicting the RCA recorded at `executor.go`; the live
  run logged `--var PR_HEAD_SHA=`.
- **`teardownVenue`/`teardownLaneBeds` duplicated the venue lifecycle in the
  domain-neutral engine** and got it wrong twice: it hardcoded the eval-omarchy
  golden entity and a `check-omarchy-pr-<pr>-vm`/`-vm-probe` domain scheme,
  resolved the bed refs against the PROCESS env (not the lane's run context),
  and used the signal-cancelled ctx (so it was skipped precisely on abort).
  Venue lifecycle now has ONE owner: the `ade` stage, whose `runAdeBed` destroys
  its `--keep-venue` domain via a deferred `destroyVenue` on a
  `context.WithoutCancel`-detached context — so a failure, a provider error and a
  SIGTERM all still tear down. The batch-level duplicate is deleted.
- **The hardcoded `check-omarchy-pr-<pr>-vm` fallback existed in three more
  sites** (`ade.go` ×2, `adekit.go`). `#AdeStage.bed` is schema-REQUIRED, so an
  empty bed is a caller defect: all three now fail loud instead of silently
  mis-targeting a non-omarchy project.
- **No signal handling** — a killed engine orphaned its child check run holding
  the per-bed flock, so every later lane died on "check bed … already running".
  Added `signal.NotifyContext`.
- **The ledger dump path was fixed** (`workdir/stage-findings.yml`), so
  concurrent lanes overwrote each other's forensics. Now per-lane.
- **`StageResult.Duration` was measured but dropped from the dump**, so the one
  artifact that could answer "where did the time go?" had no timing. Recorded.
- **`runCheckRun`/`teardownBed` were dead code** and hardcoded
  `exec.Command("charly", …)`. Deleted (R5).
- **`probeHeadFreshness` shelled out to a hand-rolled `gh api`** and reported a
  bare "gh failed" — the class `tools.go`'s own header RCA'd. Now the canonical
  ghkit client.
- **The `pipeline` agent-tool group** declared nine tools with empty parameter
  schemas and dispatched them with an empty input map, so each passed vacuously
  or failed spuriously, while duplicating the schema-validated probe STAGE
  surface and being unused. Deleted (R3/R5).
- **`probeSequencing` matched a hardcoded omarchy regex** (a vacuous green
  elsewhere) and **`probeGoldenPresent` silently substituted a hardcoded
  omarchy path**. Both now driven by their declared inputs.
- **The ADE summary was truncated to the last 400 bytes**, slicing mid-word and
  dropping the diagnosis. `lastLines` keeps whole trailing lines.

Also deleted `lanes_ok`, an unreachable alias of the sequencing gate whose
description claimed it "reports the concurrency budget".

## Rulebook compliance

- **R1 (RCA every anomaly)** — every one of the eleven defects above was
  root-caused before remediation; the two per-lane collisions were traced to the
  already-documented class at `executor.go` (RCA 2026.252.2210).

  duplicate `pipeline` agent-tool group and the unreachable `lanes_ok` alias

  SSE parser, the dead `runCheckRun`/`teardownBed`, and the broken tool group

  run on the frozen head and are pasted above.
- **R10 (fresh disposable proof)** — the real `eval-pr-plan` lane was run
  end-to-end against real `omacom/omarchy` PRs on real disposable VMs, plus real
  ollama over the real SDK client.

  is generated and proven reproducible.
- No `go.work` is added; no submodule is edited; no force-push.
