# 2026.324.0037 — feat(pipeline)!: take the contract's #Retry and delete the timed #PipelineRetry

## Summary

**`plugin-pipeline` stops authoring its own timed retry and takes the contract's `#Retry`.** This is the consumer leg of the chain `spec` started and `sdk` carried.

```cue
// removed
// #PipelineRetry — lobster `retry`: retry the failed step up to `max` attempts.
#PipelineRetry: {
	max?:      int & >0
	delay_ms?: int & >=0 @go(DelayMs)
	factor?:   number & >=1
}
retry?:      #PipelineRetry

// now
retry?:      schema.#Retry
```

**Why the contract's shape is the right one**, in `spec/schema/stage.cue`'s own words:

> *"D-FLOW-2: a stage's repetition is a DECLARED, BOUNDED count. It never repeats a failed plugin call (D-PROTO-7) and is never blind (D-LAW-5), which is why `attempt` is bounded by `#Count` and `until` names the condition that ends it. This REPLACES plugin-pipeline's timed `#PipelineRetry{max, delay_ms, factor}`."*

**So the deletion is what the contract asked for, not a local preference.** `#Retry` carries `attempt?: #Count`, `until?: #Duration` and `interval` — a declared count with a named terminating condition, instead of `max` attempts with an unbounded exponential `factor`.

**Consumers:** `pipeline.cue`'s `#PipelineFlow.retry` is the only reader. No Go in this repo touches `Retry` — the only Go artefact is the generated field, which now types as `spec.Retry` instead of the local `PipelineRetry`.
