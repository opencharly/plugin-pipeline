# 2026.277.2104 — feat(pipeline)!: the workflow front-end cutover — lifted verb providers, the retired executor, and the resume + schedule legs

## Summary

The **workflow front-end cutover** for `kind:pipeline` — leg 6 of `opencharly/charly#758`
(`Part of #758`; that issue stays open, this is one leg of the wave).

`kind:pipeline` stops being a home-grown grammar with its own executor and becomes a
**lobster-syntax front-end that lowers to the `workflow` provider class**, while the seven
stage kinds that used to be private to `runStage` become **ordinary `verb:` providers
reachable from any plan**. The in-process executor is deleted.

### What changed, and why

**1. The seven stage kinds are lifted into `verb:` providers (`!`).** Before, `agent`,
`probe`, `ade`, `generate`, `emit`, `media` and `gate` existed only as `kind: pipeline`
stages: no plan anywhere else could reach them. They are now declared in `NewMeta` as
`{Class: "verb", Word: <word>, InputDef: "#Pipeline<Word>Input"}` (`plugin.go`) and routed by
`Invoke`'s `OpRun` arm, so a `<word>: <input>` step reaches them from any plan — a task, a
candy plan, or a pipeline step. The bodies **moved**, they were not rewritten (R3): `runStage`,
`render.go`, `media.go`, `ade.go`, `probes.go`, `agent.go` and `emit.go` keep only what the
verb no longer owns. The new `verb_env.go` is the single `verbEnv` the standalone dispatch
path constructs; `refs.go` is the ref grammar the bodies share.

**2. The in-process executor is retired, and `run` lowers instead.** `executor.go` (−817),
`batch.go` (−121) and `plan_refs.go` (−33), with their tests, are **deleted** (R5 — the old
path is gone in this same PR). `charly pipeline run <entity>` now resolves the authored
entity, validates it (`workflowkit.ValidatePipeline`), lowers it to the
`(workflow.lobster, charly.yml)` pair with `workflowkit.Lower`, and dispatches `workflow-run`
to the **`workflow` provider class**. Execution is the engine's — plugin-lobster today, a
future `github-actions` engine unchanged.

**3. The `resume` leg.** `charly pipeline resume <name> [--approve yes|no|--response-json|--cancel]`.
The front-end records the paused gate handle beside the lowered pair (`genDirOf` +
`recordPending`), so `resume <name>` finds the paused run **without being handed a token** —
writer and reader agree on one path, which is what the bed asserts by asserting the file.

**4. The `schedule` leg.** `charly pipeline schedule apply|list|remove|run-now` — the front-end
half of the systemd-timer surface (the units themselves are the engine's).

**5. The staged-verb schema contract.** `schema/pipeline.cue` declares the per-verb input
shapes under namespaced defs (`#Pipeline<Word>Input`), and `params/cue_types_gen.go` is the
regenerated source (`cue exp gengotypes`, pinned to `cuelang.org/go v0.16.1`).

**6. Tests added** (all new files): `cli_workflow_test.go` (+274) drives the CLI legs;
`verb_reach_test.go` (+220) is the anti-reregression lock that each lifted word is *declared*
with its frozen input def and *routed* rather than falling through to the pipeline CLI;
`verb_input_defs_test.go` (+104) pins the input shapes; `verb_ade_head_test.go` (+76) locks the
`ade` fallback's head lookup (see **R1** below).

**7. The R10 bed** — `charly.yml` is new on this branch (+578): `check-pipeline-local`, a
`disposable: true` bed that composes the plugin and witnesses the front-end end to end.

**8. Docs** — `AGENTS.md` (+22/−8) and `README.md` (+34/−16) restate the front-end's new
shape; the candy entity's own `charly.yml` (+35/−17) follows it.

Requires `github.com/opencharly/sdk v0.2026276.255` and `github.com/opencharly/spec
v0.2026277.1407` — both released tags, both merged before this branch.

**File accounting (54 files, +3331/−2674):** 13 added, 8 deleted, 33 modified. The counts
above are the measured `git diff --numstat --diff-filter=ADM -M origin/main...HEAD` values;
nothing is estimated.

### What this unblocks

`opencharly/plugin-lobster#1` is BLOCKED on exactly this: its `schedule` witness was produced
against an **unmerged sibling worktree**, and the two offered exits were a maintainer sign-off
or a run against a **merged driver**. This PR is that driver. On merge + tag, plugin-lobster
re-runs both of its beds with `--dev-plugin plugin-pipeline=<checkout@merged-tag>`, so the
driver source is a merged commit — no sign-off needed.

**The lifted verbs, and exactly which of them the bed executes live.** The verdict on the
previous head asked for this to be stated precisely instead of blanket-claimed. Seven verb
bodies were lifted out of the old stage dispatch; the bed's coverage of them is:

| lifted verb | executed live in the bed? | where |
|---|---|---|
| `gate` | **yes** — a real condition, the **true** arm (step 8's fixture is `condition: "true"`); the false arm is asserted by `verb_reach_test.go` as `gate : condition false: 1 == 2`, a unit test, not a live run | step 8 |
| `generate` | **yes** — renders `hello ${who}` with its typed var into `rendered.txt` | step 9 |
| `emit` | **yes** — validates `{name: rendered}` against a literal CUE source (`#Record: {name: string}`) and serializes `emitted.yml` | step 9 |
| `probe` | **yes** — reads the emitted artifact off disk, **plus a negative control**: a second fixture probes a path that does not exist and must carry the run to `status=error`, so a `probe` that returned pass unconditionally could not satisfy the step | step 9 |
| `agent` | **no** — needs a live LLM endpoint | — |
| `ade` | **no** — needs a rendered host bed | — |
| `media` | **no** — needs `/tmp/pr-<n>` capture artifacts | — |

`generate` and `emit` write files, which is exactly why `verb_reach_test.go` pins **routing**
only for them (a body unit test would need a workdir), so the bed is where their bodies are
proven alive: `generate` renders its inline template with the typed var into the absolute `out`,
and `emit` validates and serializes. Both were dead before this lift.

`agent`, `ade` and `media` are **not** bed-executed. Their bodies need, respectively, a live LLM
endpoint, a rendered host bed, and the `/tmp/pr-<n>` capture artifacts a real PR lane leaves
behind — none of which a disposable local bed can honestly manufacture, and faking any of them
would violate "live or skip — never fake a live service". They are covered by
`verb_reach_test.go`'s routing lock (each word reaches its body and fails **inside** it, never
with "unknown verb") plus their own unit tests. That lock is a routing proof, not a live proof,
and this body does not claim it as one.

## Rulebook compliance

- **R0 — skills first.** `/charly-internals:git-workflow` before any git/PR action;
  `/charly-pipeline:pipeline`, `/charly-internals:plugin`, `/charly-internals:go` before the
  code change; `/charly-check:check` for the bed.
- **R1 — RCA every anomaly.** Two load-gate failures surfaced while authoring step 9 and were
  root-caused, not worked around: a step-level verb key is **not** an execution arm ("no
  execution arm — set exactly one of `run`/`pipeline`/…/`plan`/…"), and inside `plan:` the step
  still needs an **intent keyword** ("`plan[0]` has no intent keyword
  (`run`/`check`/`agent-run`/`agent-check`/`include`)"). Step 9 carries that as a comment so the
  next reader does not re-derive it.
- **R1 (second anomaly, fixed in this commit) — the `ade` fallback's head came from a dead
  resolver.** `verb_ade.go` passed `rc.resolveRefs("$env.PR_HEAD_SHA")` to the external
  check-run fallback, under a comment asserting the resolver is wired back to the run context's
  env map. Measured, that is false: `standaloneVerbEnv` (`verb_env.go:65`) is the **only**
  production `verbEnv` constructor in the package and wires `resolve` to the identity function
  (`refs.go:33` short-circuits to it), so `refs.go`'s `$env.X` grammar is dead on that path and
  `resolveRefs` returns the **literal** `$env.PR_HEAD_SHA` — which the fallback would render as
  `--var PR_HEAD_SHA=$env.PR_HEAD_SHA`, a string that looks like a head and is carried into the
  bed's evidence as one. The head is now a **map read** of the run context (`adeLaneHead()`),
  exactly the lookup the retired in-process executor performed
  (`origin/main:executor.go:268`, an operator pin winning), and the false comment is replaced by
  one that states the trap **and** the consequence: a standalone dispatch carries no per-run map,
  so the read yields `""` — a missing run context, which is honest.
  `verb_ade_head_test.go` locks it: the bound map wins; the standalone env yields `""` even with
  `PR_HEAD_SHA` set in the process env (the process-global the concurrent lanes raced, RCA
  2026.252.2210); the identity-resolver premise the rationale rests on is asserted so it cannot
  rot silently; and the **call site** is locked structurally, because driving it behaviourally
  would need a real `charly` on `PATH` and a unit test must never stand a stub in for that
  boundary. Proved to bite, not just to pass: re-introducing
  `rc.resolveRefs("$env.PR_HEAD_SHA")` at the call site makes it FAIL
  (`verb_ade_head_test.go:68` and `:71`), and restoring the file makes it pass again.
- **R3 — no duplication.** The lifted bodies **moved**; each has exactly one caller. `verb_env.go`
  is the one `verbEnv` the standalone path builds. `emit`'s schema machinery stays in `emit.go`

- **R4 — no workarounds.** The bed was invoked with **no** scope-shrinking flag — no
